## koment procedure

- Before editing an existing file, call `koment_get` for it and read every annotation. Search with `koment_search` before changing a non-obvious decision.
- Treat ambiguous, drifted and orphaned annotations as history, never as current fact.
- Do not add explanatory inline comments. Prefer a better name, extraction, a named type or constant, or clearer structure; then record local rationale with `koment_add` and honest agent authorship.
- Completed comment intent must use `koment_convert_comment`. Keeping an inline comment requires `koment_acknowledge_comment` with the explicit acknowledgement set to true.
- Before finishing, run `koment check`, `koment comments check` and `koment agents check`. Do not report success while any fails.
- Releases follow `docs/releasing.md` exactly. Published versions are permanent. Never publish an artifact by hand, never hand-edit a version, and get explicit human approval before merging a release pull request.

## How that applies here

The block above is generated by `koment agents install` and describes koment in
general. Two of its lines do not fit this repository.

**`koment_convert_comment` does not work here.** koment's comment detection is
Go-only, and this repository is Kubernetes YAML, Just recipes and shell. Asking
it to convert a YAML comment fails with `no comment detector for <file>`. There
is no automatic migration and no batch mode.

Move a comment into koment by hand, in this order:

1. Read the comment and decide whether it is rationale or narration. Narration
   gets deleted, not recorded.
2. `koment add <file> --excerpt '<verbatim snippet of the code>' --kind why --body -`
   anchored to **the code the comment describes**, never to the comment text.
   An annotation anchored to a comment orphans the moment the comment goes.
3. Delete the comment.
4. `koment check`.

**There are no releases here.** This repository is continuously reconciled by
Flux; nothing is versioned or published, and there is no `docs/releasing.md`.

**`koment comments check` finds nothing**, because it only walks `*.go`. It will
exit zero and prove nothing. `koment check` is the one that matters.

## Comments in this repository

Do not add comments to YAML, Just or shell files. The only comments that belong
here are ones copied verbatim from upstream `onedr0p/home-ops` or
`home-operations`, kept identical so the diff against upstream stays readable.
Rationale of your own goes in a koment annotation.
