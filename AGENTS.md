# KOMENT PROCEDURE — MANDATORY

This file is a managed contract. The repository enforces it with
client hooks and a required CI status. You MUST follow every rule.
Partial compliance is a bug.

## Before any edit or write to an existing file

- You MUST invoke `koment_get`("<repository-relative path>") via MCP
  and treat the returned annotations as the authoritative context for
  the file. An annotation whose status is `ambiguous`, `drifted`
  or `orphaned` is history, not current fact; surface it to the human
  before continuing.
- You MUST invoke `koment_search`("<topic>") before any non-obvious
  structural decision that another file may already explain.

## Adding or changing a comment is FORBIDDEN

- You MUST NOT write an ordinary inline comment in source. The
  repository classifies every comment group and rejects ordinary ones
  on the protected branch. The only exceptions are the intrinsic
  classes enabled in `.koment/policy.yaml` (toolchain directives,
  generated markers, upstream links, `// Deprecated:`, godoc on
  exported identifiers) and any additional pattern declared under
  `spec.comments.allowedAnnotations`.
- Before keeping a comment, you MUST attempt in order: rename the
  thing, extract a function whose name is the comment you were about
  to write, introduce a named type or constant, restructure so the
  invariant is obvious from control flow. If the rationale still needs
  saying, call `koment_add` bound to the code with `--excerpt`
  and record yourself honestly as an agent.
- If a comment already exists in source, you MUST call
  `koment_convert_comment` first to record it as an annotation,
  then remove the comment from source.
- Keeping an inline comment requires `koment_acknowledge_comment`
  with `acknowledge_inline_comment: true` and a human-readable body.
  The acknowledgement is auditable.

## Before you stop

- You MUST run `koment check`, `koment comments check` and
  `koment agents check`. You MUST NOT report success while any
  fails.

## How that applies here

The block above is generated by `koment bootstrap` and describes koment in
general. Four of its points need adjusting for this repository.

**The escape hatch is closed.** The managed block offers
`koment_acknowledge_comment` as a way to keep an inline comment by acknowledging
it. Never use it here. There is no comment worth keeping that an annotation
cannot hold better, and reaching for it means you have found rationale — record
that with `koment_add` and delete the comment.

**`koment_convert_comment` does not work here.** koment's comment detection is
Go-only, and this repository is Kubernetes YAML, Just recipes and shell. Asking
it to convert a YAML comment fails with `no comment detector for <file>`. There
is no automatic migration and no batch mode.

Move a comment into koment by hand, in this order:

1. Read the comment and decide whether it is rationale or narration. Narration
   gets deleted, not recorded.
2. **Delete the comment first.** This inverts the order the managed block
   implies, and the order matters. `--excerpt` is matched verbatim, so a
   trailing comment on the same line (`- name: foo # because bar`) makes the
   clean excerpt fail with `excerpt not found`. koment also snapshots the
   surrounding lines as anchor context at add time, so annotating before
   deleting leaves the annotation reporting `moved` forever.
3. `koment add <file> --excerpt '<verbatim snippet of the code>' --kind why --body -`
   anchored to **the code the comment described**, never to the comment text.
   An annotation anchored to a comment orphans the moment the comment goes.
4. `koment check`. Repair a bad anchor with
   `koment reanchor <id> --excerpt '<verbatim text>'`, which keeps the id.

**There are no releases here.** This repository is continuously reconciled by
Flux; nothing is versioned or published, and there is no `docs/releasing.md`.

**`koment comments check` finds nothing**, because it only walks `*.go`. It will
exit zero and prove nothing. `koment check` is the one that matters.

## Comments in this repository

**Never write a comment.** Not in YAML, not in Just, not in shell, not in a
Python or shell script embedded in a ConfigMap. There is no threshold of "but
this one is genuinely useful" that unlocks it: that feeling is the signal you
have rationale, and rationale goes in `koment_add`. A comment added today is a
comment that silently goes stale, drifts from the code beside it, and gets
believed by the next reader anyway. Annotations are checked by `koment check`;
comments are checked by nobody.

Exactly two kinds of `#` line are permitted, and neither of them is you
explaining something:

- **Machine-read directives**, which tooling parses and would break without:
  `# yaml-language-server: $schema=`, `# renovate:`, `# zizmor: ignore[...]`,
  shebangs, the `# vX.Y.Z` version pins Renovate maintains beside pinned action
  SHAs, and the `.justfile` comments that `just --list` renders as recipe docs.
- **Upstream lines copied verbatim** from `onedr0p/home-ops` or
  `home-operations`, kept byte-identical so the diff against upstream stays
  readable. Copied, never composed — if you wrote the words, it is not this.

Everything else is a koment annotation. If you cannot tell which of the two a
line is, it is neither.
